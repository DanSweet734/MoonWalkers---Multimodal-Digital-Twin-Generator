# 2026-11-11 - Pipeline D reads PDF catalogs

## Goal
Integrate PDF catalog extraction into Pipeline D (Sarkis's request): a `pdf_catalog` source
gives cited facts in a `PipelineResult`, instead of the "not implemented" issue.

## What was done
- **Decision [0034](../decisions/0034-pipeline-d-pdf-catalogs.md), proposed.** The parser runs
  in Pipeline D's own environment as a subprocess; each printed "label ..... value" line and
  each labelled part number becomes a text fact cited to its page; a catalog never sets the
  machine's identity. Nothing was installed today, and the contract is unchanged.
- **New `d/catalog_worker.py`:** JSON in, JSON out. It runs `catalog_parser.py` in a temporary
  folder and returns each page's text, candidates and image count.
- **New `d/catalog_facts.py`:** pure reading of the page text (leader lines, headings, contents
  pages). It imports no PDF library, so the backend's tests cover it.
- **`d/pipeline.py`:** `CatalogReader`, `CatalogPipeline._pdf()`, and one `run_worker()` shared
  with the browser reader. `produced_by` is now "pipeline-d catalog 0.2.0".
- **`d/catalog_parser.py`:** `part_candidates()` requires a digit and drops trailing
  punctuation, so "this model is quiet" no longer gives the candidate `is` (found on
  2026-11-10). Lint fixes.
- **Lint:** fixed the three errors left on 2026-11-10 (`browser_worker.py`, `octopart.py`) and
  formatted `test_pipeline_d.py`.
- **`octopart_agent/requirements.txt`:** pdfminer.six added beside Playwright.
- **Docs:** `docs/setup/pipeline-d-octopart.md` (new "PDF catalogs" section), the pipeline
  guide's status, the README status row, `docs/poc-plan.md`, `example.env`.

## Known inaccuracies and limits
- Values are text as printed: no SI conversion, no shared keys such as `spindle_travel`.
- The manual covers two models. Its T33901 data sheet (pp. 8-9) and T33902 data sheet
  (pp. 10-11) both come through; only the page tells them apart.
- Tool and quantity lists come through as facts (for example p. 44, "Open-End Wrench 14mm ...
  1"), and some headings are fragments of a sentence (p. 15).
- The parts list's 159 part numbers give no facts: its tables have no leader dots.
- The two rules that leave out contents pages and number lists are my own [INFERENCE], tuned on
  one manual.
- Not checked in the dashboard or through the agent's `add_input` and `submit_twin`.
