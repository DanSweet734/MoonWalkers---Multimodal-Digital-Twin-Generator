## A plan from another chat, checked against the repository
Daniel shared a week's plan from another conversation. It proposes:
- contract v0.2;
- an exporter tested first on a box-and-cylinder drill press, with a mimic-joint test;
- a spike on cutting a model into several parts;
- sources for each teammate's pipeline on the T33901;
- team plumbing;
- automatic quote checks;
- three success levels for the drill press.

What its claims rest on:
- **"Teammates can't build real pipelines until the format can describe a drill press":
  overstated.** Contract v0.1.0 (`contracts/pipeline_result.py`) already has:
  - `prismatic` joints with `lower_limit` and `upper_limit` (m);
  - a parent and a child part on every joint, which make a tree;
  - control kinds `state_machine` and `lookup_table`, with a free-form `spec`.

  What it lacks is linked joints (leader, follower, ratio) and joint modes (spring return,
  locked). Merge rules are orchestrator behaviour, not necessarily contract fields (decision
  0009).
- **"Grizzly blocked automated fetches before": not in the record.** The worklogs record only
  haascnc.com's HTTP 403. The Grizzly manual PDF downloaded normally on 2026-10-19. The Grizzly
  product page has not been tried.
- **"The manual's parts breakdown (Section 9)": correct.** Its sections end with "SECTION 9:
  PARTS". The parts pages (PDF pp. 49-53) name the quill, rack, pinion, column, crank, spring and
  depth stop.
- **"main is protected; contract changes need two reviewers": not available as things stand.**
  `gh api .../branches/main/protection` answered "Upgrade to GitHub Pro or make this repository
  public to enable this feature." (HTTP 403). The repository stays private.
- **"Tests and linting run on every pull request":** there is no CI yet (no `.github/workflows`).
- **The order is right:** exporter on primitives first, then real meshes. That is what Phase 2
  did (decision 0010).

The plan is not adopted here. Daniel decides what goes into the new chat's phase plan.
