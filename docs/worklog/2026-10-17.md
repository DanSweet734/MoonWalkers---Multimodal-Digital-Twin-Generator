- **Validator evaluation** (broken copies of the test twin; table in the research note):
  - NVIDIA's validator caught a missing joint body and missing normals.
  - It missed a triangle collider on a moving body and a joint to a non-rigid prim.
  - Ours catches all of those except normals; the test suite now runs both.
- **Hiccups**, all resolved:
  - **Native crash.** The first export crashed (exit code 3, Windows fatal exception 0x80000003 in
    `export_twin`). `build_stage(...).GetRootLayer().ExportToString()` used a temporary stage, which
    was freed while its anonymous root layer was still needed [INFERENCE from the fix]. Keeping a
    reference fixed it. The same mistake in one test gave "Accessed schema on invalid prim"; fixed
    the same way.
  - **NVIDIA validator on the first files:** `NormalsExistChecker` errors ("Either normals should be
    authored or subdivision should be set to Catmull-Clark or Loop") and `WeldChecker` warnings.
    Meshes are now welded, with flat face-varying normals.
  - **Our first validator missed** a joint to a missing prim and a joint to a non-rigid prim, because
    OpenUSD's physics parser drops or re-points such joints. Added direct joint-relationship checks.
  - **assetInfo:** `identifier` is an asset (file) path, so the twin id stored there read back as
    empty. Removed it; the twin id is in `customData`.
  - **Deprecated API:** `UsdPhysics.LoadUsdPhysicsFromRange` warns that it is deprecated; switched to
    `UsdPhysicsLoadStageFromPrimRange`.
  - **Validator API keyword:** `ValidationEngine(initRules=...)` raised `TypeError`; the keyword is
    `init_rules`.
  - **Wrong guessed URL:** a guessed Isaac Sim download URL returned 404. The real link, taken from
    the download page, answers 200 with 10,528,731,217 bytes.
  - **Smaller fixes:** ruff's broader rules flagged 5 issues in the new code (long lines, PERF102,
    ISC004, an unused variable); fixed. A function named `test_twin` would have been collected by
    pytest, so it was renamed `build_test_twin`.
