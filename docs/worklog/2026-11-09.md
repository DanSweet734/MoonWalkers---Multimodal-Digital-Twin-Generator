## Tool gap 5: the preview finds what NVIDIA's validator would warn about
**Goal:** `preview_twin` reports zero-area faces and non-manifold points per part. Until now only
a dry-run build and NVIDIA's validator found them, which cost the agent's T33901 build two dry
runs (drill-press report, 7.3, item 5).

### What was built
- **`mesh_tools.mesh_faults`** works by vertex index, as the exporter writes the points. It
  finds:
  - zero-area faces (cross product exactly zero in 32-bit floats, as USD's points are);
  - edges with more than two faces;
  - points whose faces form more than one fan;
  - neighbouring faces wound opposite ways.

  The definitions are NVIDIA's (omniverse-asset-validator 1.18.0, `_geometry_checker.py` and
  `_mesh_tools.py`). That validator is a dev dependency, so the check is our own numpy.
- **The two previews.**
  - The several-part preview adds a warning per faulty part, with up to eight points in model
    units after orienting (`AssembledModel.origin_model_units` is new).
  - The one-spindle preview gains `mesh_faults`.
  - The MCP tool's description and report fields say so.

### Checked against NVIDIA's own code
`compare_faults.py` and `stress_faults.py` are in the scratchpad.
- **17 T33901 parts:** the same counts as `check_manifold_elements`. All were clean.
- **12 broken face subsets of a generated mesh** (thousands of bowtie points, duplicated and

## Tool gap 4: `fit_circles` within a box and across any direction
**Goal:** measure one round part where a slice crosses several (drill-press report, 7.3, item 4;
the lab's machines plan says the arm's links lie at angles).

### What was built
- **`mesh_tools.fit_circles`** and **`fit_circles_along`** take `box`, the lowest and highest
  (x, y, z) to keep: surface samples outside it are dropped before the slices are cut. `box_within`
  builds one from ranges on some axes, leaving the others open.
- **`fit_circles_across(mesh, direction, positions, box=...)`** slices across any direction. A
  link at an angle is cut in an ellipse by a slice across an axis. A position is the distance
  along the unit direction from the origin, and each centre is a point in the mesh's frame.
- **One code path:** the fits share `_fit_across`, which projects the samples onto three
  right-handed unit axes (`slice_axes`). Along x, y or z those are the old cyclic orders.
- **Where the agent and the user reach it:**
  - the MCP tool `fit_circles`: `along` is `"x"`, `"y"`, `"z"` or `[dx, dy, dz]`, and `within`
    is `{"x": [lo, hi], ...}` in model units. The report repeats `within`.
  - the CLI: `inspect ... --circles-along DX,DY,DZ` and `--within AXIS LO HI` (repeatable).
